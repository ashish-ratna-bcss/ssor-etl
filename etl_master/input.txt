# Master ETL Process Configuration File
# This file defines the sequence of ETL processes to run daily.
# The Master ETL script will read this file top-to-bottom and execute each process sequentially.
#
# Format:
# <Working Directory> ; <Command to Execute>
#
# Instructions:
# 1. Add each ETL process on a new line.
# 2. Specify the full path to the directory where the process should run.
# 3. Separate the directory and the command with a semicolon (;).
# 4. Lines starting with # are ignored.
#
# --- Ordering rationale (verified against each ETL's actual DB checks, not
# just comments -- see etl_master's dependency audit) ---
#   1  hierarchy    : no dependencies.
#   2  crimes       : hard-depends on hierarchy (PS_CODE validated against it).
#   3  accused      : hard-depends on crimes; soft-creates person stub rows.
#   4  persons      : depends on accused (backfills the stub rows accused just
#                      created -- not a hard gate, but a worklist source, so it
#                      must run after accused to have anything to enrich).
#   5-9  properties, IR, Disposal, arrests, mo_seizures : each only
#                      hard-depends on crimes; independent of each other.
#  10  stolen_automobiles : hard-depends on crimes only -- same tier as 5-9.
#  11  fpb_accused  : hard-depends on crimes only (reads FIR_NUM/PS_CODE
#                      straight from the crimes table to drive its lookups).
#  12  fsl_case_property : soft-depends on mo_seizures (its MO-match audit
#                      check) -- placed right after mo_seizures/stolen/fpb
#                      instead of trailing chargesheets like before.
#  13  chargesheets : hard-depends on crimes only.
#  14  updated_chargesheet : logically follows chargesheets (same document,
#                      later revision) -- both hard-depend on crimes.
#  15  update_file_id : depends on persons (its persons-branch worklist reads
#                      `SELECT DISTINCT person_id FROM persons`) -- persons
#                      already ran at step 4, so this is satisfied regardless
#                      of where it sits after that; kept last among data
#                      ETLs since it also mirrors file references created by
#                      every other data type above.
#  16  files_download_media_server : hard-depends on update_file_id having
#                      populated the files table.
#  17  update_file_extentions : hard-depends on files_download_media_server
#                      having actually downloaded files (needs real file_path).
#

# --- User Process Definitions ---
